# 00. Анализ ТЗ и принятые решения

> Первый шаг проекта. ИИ-агент (Claude Code) прочитал `TZ.pdf` в режиме только чтения и подготовил анализ, люди ответили на открытые вопросы. Дата: 19.11.2026.

## 1. Суть и критерии

Сейчас учёба студента раскидана по разным местам: расписание на сайте, оценки в отдельной системе, справки через очередь, объявления в чатах. Делаем один кабинет, где всё это собрано вместе. Он удобен с телефона (от 360 px), хорошо выглядит и безопасен.

Вуз вымышленный: **AI High School (Высшая Школа ИИ)**. Факультеты, группы, преподаватели, студенты и логотип тоже придуманы. На сайте есть пометка «концепт для конкурса».

**Обязательное ядро:**
1. Вход и профиль: ФИО, факультет, направление, курс, группа.
2. Расписание: сегодня и неделя, аудитория, преподаватель, заметные переносы.
3. Успеваемость: оценки, зачёты, сессия, сводка «как у меня дела».
4. Заявки и справки: подача онлайн и статус.
5. Уведомления: новости деканата, дедлайны, изменения.

**Плюс:** кабинет сотрудника деканата. Сотрудник обрабатывает заявки и меняет их статус, а студент видит изменение и получает уведомление.

**Что сдаём:**
- ссылку и тестовые аккаунты (2 студента и сотрудник);
- публичный репозиторий на GitHub;
- PDF о процессе: проблема, ИИ-инструменты, промпты по этапам, скриншоты, как устроены вход и защита, что сделано вручную;
- видео до 5 минут.

| Критерий (по 10 баллов) | Что из этого следует |
|---|---|
| Проработанность идеи | ядро делаем целиком, плюс две сильные идеи: калькулятор «что нужно для стипендии / закрыть сессию» и справка с QR-проверкой |
| Масштаб использования ИИ в разработке | CLAUDE.md и `.claude/rules/`, журнал промптов каждого агента с первого часа, фиксируем ошибки ИИ и как их исправили |
| Имплементация | постоянная БД, проверка доступа в каждом запросе, IDOR-тесты, e2e на 360 px, рабочие тестовые аккаунты |
| Качество | своя дизайн-система, состояния loading/empty/error, доступность, скорость |

## 2. Стек

Монорепозиторий на TypeScript с pnpm workspaces.

| Слой | Выбор |
|---|---|
| Рантайм / пакеты | Node.js 24 LTS, pnpm 10 |
| Язык | TypeScript (strict) |
| Контракт | Zod 4: общие схемы и типы для фронта и бэка |
| API | Hono 4 + `@hono/node-server` + `@hono/zod-validator` |
| БД | Drizzle ORM; PostgreSQL в проде, PGlite (Postgres на WASM) в dev и тестах |
| Пароли / сессии | argon2id (`@node-rs/argon2`); серверные сессии в httpOnly cookie |
| Фронт | React 19 + Vite + React Router 7 + TanStack Query 5 |
| UI | Tailwind CSS 4 + shadcn/ui (Radix) + Lucide; шрифты под OFL |
| PWA / моки | vite-plugin-pwa, MSW |
| Тесты / линт | Vitest, Playwright, Biome |
| Деплой | Docker на одной ВМ: API (раздаёт и SPA) + Postgres + Caddy (HTTPS) |

Точные версии закрепляем на этапе 0.

**Почему так:**
- Одинаково работает на Windows и Linux: PGlite не требует Docker и нативной сборки, у argon2 есть готовые бинарники.
- Один язык на всём проекте.
- Стык фронта и бэка типизирован через общий контракт.
- API без состояния + Postgres масштабируются горизонтально, как требует ТЗ.

**Отвергнутые альтернативы:**
- Next.js full-stack: фронт и бэк живут в одних файлах, а Vercel из РФ работает нестабильно.
- FastAPI + React: два языка и кодогенерация типов.

## 3. Архитектура

```
packages/contract/   Zod-схемы DTO, таблица роутов, enum статусов — общий язык фронта и бэка
apps/api/            Hono: auth · profile · schedule · grades · requests · notifications · staff · certificates (QR)
                     db/: schema, migrations, seed
apps/web/            React SPA: ui/ (дизайн-система) · features/* · api/ (клиент на контракте) · mocks/ (MSW) · e2e/
deploy/              Dockerfile, compose.yml (api + postgres + caddy), Caddyfile
docs/process/        анализ, журналы агентов, скриншоты — сырьё для PDF
```

- **Зависимости:** `web → contract ← api`. Фронт и бэк друг друга не импортируют, поэтому модули можно делать параллельно.
- **Прод:** одна ВМ, один origin. Caddy (HTTPS) проксирует на API, API отдаёт собранную SPA. CORS не нужен, cookie same-site.
- **Безопасность:**
  - студенческие роуты только `/api/me/*`, id студента берётся из сессии;
  - заявку ищем по `id AND student_id`, на чужую отвечаем 404;
  - `/api/staff/*` закрыт ролью;
  - пароли хешируются argon2id, секреты лежат только в env на сервере;
  - на логин стоит rate-limit;
  - QR со справки ведёт на публичную страницу проверки по случайному токену, данных там минимум.

## 5. Риски

1. **Сроки.** Около 3,5 дня. MVP нужен к вечеру 20.11, отправка вечером 22.11, а не в 23:59.
2. **Хостинг.** Стартовый грант Yandex Cloud могут одобрить не сразу. Запасной вариант: российский VPS. Ранний деплой ждёт ВМ, остальной этап 0 не ждёт.
3. **Домен из GitHub Student Pack.** Верификация может занять дни. Запасной вариант: `<ip>.sslip.io` + Let's Encrypt через Caddy.
4. **Docker Hub из РФ** бывает недоступен. Запасной вариант: зеркало (`mirror.gcr.io`) или сборка в GitHub Actions с публикацией в GHCR / Yandex Container Registry.
5. **Публичный репозиторий.** Ни одного секрета в git, только `.env.example`. Пароли тестовых аккаунтов вымышленные и всё равно передаются жюри.
6. **Жюри меняет общие данные.** Нужен сброс демо-данных.
7. **Даты.** Сид строится относительно текущей недели по МСК, есть субботние пары и блок «ближайшее занятие». Так «Сегодня» не опустеет до 28.11 и в выходные.
8. **Две ОС в команде.** Linux и Windows. Поэтому никаких bash-скриптов, только LF и CI на обеих ОС.
9. **Журнал процесса** — половина критерия 2. Ведём его с первого часа.

### Неясные места ТЗ и как мы их закрыли

| В ТЗ | Решение |
|---|---|
| «гибкий с точки зрения масштабирования» | API без состояния + Postgres; объясняем в PDF |
| парсинг открытого расписания разрешён, но в нём настоящие ФИО | расписание целиком вымышленное |
| «вход по логину и паролю (или другим способом)» | логин и пароль |
| кабинет сотрудника «если есть» | делаем: без него статус заявки не меняется вживую |

## 6. Принятые решения

- Вуз вымышленный: «AI High School», реальных вузов и ФИО нет.
- Хостинг: ВМ в Yandex Cloud (запасной вариант — российский VPS), Docker: API + Postgres + Caddy. Домен из GitHub Student Pack. Зарубежные хостинги не рассматриваем.
- Стек: TS-монорепо (Hono + Drizzle/Postgres + React/Vite).
- ИИ-функций внутри кабинета нет. ИИ-ассистенты используются только в разработке.
- Сильные идеи: калькулятор стипендии/сессии и справка с QR-проверкой.
- Кабинет сотрудника делаем.
- Команда из двух человек, у каждого свой Claude Code: dimas (Arch Linux) и evv (Windows). Правила совместной работы описаны отдельным документом.
- Репозиторий на GitHub публичный.
