# Фразы для Claude: шпаргалка

Полные правила лежат в `docs/AI-COLLAB.md`. Перед каждой пачкой нужен `/clear` или новая сессия.

## Как пользоваться

- Фразы — это **готовые шаблоны**. Фразу без `<…>` копируйте как есть.
- `<…>` нужно заменить своим значением **вместе со скобками**: `#<номер>` → `#12`, `<текст>` → описание своими словами.
  Под каждым таким шаблоном есть пример заполнения.
- Номер задачи — это номер issue на доске. Его видно в `/board` и в отчёте пачки.
- Можно писать и своими словами, Claude поймёт. Но шаблоны надёжнее: в них уже есть ссылки на нужные
  разделы правил и понятно, где Claude должен остановиться.
- В правках и фичах пишите, **что не так и как должно быть**. Чем конкретнее, тем меньше лишних кругов и лимита.

## Короткие команды

Они появляются после подготовки проекта (skills в `.claude/skills/`). До этого используйте фразы ниже.

| Команда | Что делает |
|---|---|
| `/batch` | пачка: по одной до 3 задач, мерж, «Статус», отчёт |
| `/batch parallel` | ⚠ пачка в параллельном режиме (§14), см. предупреждение ниже |
| `/board` | состояние доски, ничего не меняет |
| `/fix <что не так и как должно быть>` | завести правку fix + p0 |
| `/proposal <что нужно и зачем>` | завести новую фичу как proposal |

Для остального команд нет, только фразы.

## Работа (оба, по кругу)

**Пачка** (`/batch`):
```
Пачка по docs/AI-COLLAB.md: по одной бери и делай до 3 свободных задач с доски, мержи, обнови Статус и остановись с отчётом.
```

**Пачка в параллельном режиме** (`/batch parallel`, §14):

> ⚠ **Осторожно.**
> - Лимит тратится примерно **в 3 раза быстрее**: работают Claude и 2 субагента.
> - Больше конфликтов при слиянии и выше риск разойтись с контрактом.
>
> Включайте, только если на доске много свободных **независимых** задач в разных модулях и лимита заметно
> больше, чем уходит на обычные пачки. Если лимит на исходе, не включайте. Режим действует только на одну пачку.

```
Пачка в параллельном режиме по §14: до 2 субагентов, каждый на одну свободную независимую задачу. Когда все закончат, остановись с отчётом.
```

**Посмотреть состояние** (`/board`; Claude ничего не меняет):
```
Покажи состояние доски: что готово, что в работе и у кого, что заблокировано, что ждёт людей. Ничего не меняй.
```

**Посмотреть результат:**
```
Обнови main, собери и запусти проект командами из CLAUDE.md и скажи, как посмотреть результат.
```

## Управление задачами

**Правка после просмотра** (`/fix <что не так и как должно быть>`):
```
Заведи на доске fix p0: <что не так и как должно быть>.
```
Пример: `/fix на странице входа при неверном пароле белый экран, а должно появиться сообщение «Неверный логин или пароль»`

**Новая фича** (`/proposal <что нужно и зачем>`):
```
Заведи на доске proposal: <что нужно и зачем>. Разбей на задачи с контрактами по §10.
```
Пример: `/proposal экспорт списка задач в CSV: кнопка на главной, скачивает все задачи пользователя`

**Одобрить или отклонить предложение:**
```
Одобряю #<номер>, #<номер>: сними с них proposal.
```
Пример: `Одобряю #21, #22: сними с них proposal.`
```
Отклоняю #<номер>: закрой с комментарием <почему>.
```
Пример: `Отклоняю #23: закрой с комментарием «не успеем к сдаче».`

**Разобрать задачи, где Claude застрял (needs-human).** Сначала, как есть:
```
Покажи задачи с needs-human и предложи варианты решения для каждой.
```
Потом для каждой задачи:
```
По #<номер> делаем так: <решение>. Запиши это в issue и сними needs-human.
```
Пример: `По #17 делаем так: вариант 2, настройки храним локально у пользователя. Запиши это в issue и сними needs-human.`

**Сменить приоритет.** `p0` — срочно, `p1` — обычный, `p2` — если останется время:
```
Поставь #<номер> приоритет <p0 / p1 / p2>.
```
Пример: `Поставь #15 приоритет p0.`

**Изменить контракт:**
```
Нужно изменить контракт из #<номер>: <что меняем и почему>. Найди всё, что от него зависит, и сделай по правилам §1.
```
Пример: `Нужно изменить контракт из #12: поиск пользователя должен возвращать пустой результат вместо ошибки, если пользователя нет. Найди всё, что от него зависит, и сделай по правилам §1.`

## Особые ситуации

**Лимит на исходе** (как есть):
```
Лимит на исходе: доделай текущую задачу, новых не бери, отчитайся.
```

**Сменить правила работы** (после этого второму нужно сделать `git pull` и `/clear`):
```
Меняем правило: <какое правило и как теперь>. Обнови docs/AI-COLLAB.md, CLAUDE.md и затронутые skills/rules отдельным PR.
```
Пример: `Меняем правило: в пачке до 2 задач, а не до 3. Обнови docs/AI-COLLAB.md, CLAUDE.md и затронутые skills/rules отдельным PR.`

**Подготовка к сдаче** (как есть):
```
Готовимся к сдаче: проверь, что main собирается и тесты зелёные, обнови README (что сделано, как запустить), перечисли незакрытые задачи.
```
