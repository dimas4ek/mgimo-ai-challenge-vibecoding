# Модуль contract

Общий язык `api` и `web`. Если контракт сломан, ломаются оба модуля.

- **Zod — единственный источник типов DTO.** Типы получаем через `z.infer`, отдельные `interface` для тех же данных не дублируем.
- Пакет зависит только от `zod`: без Node API, без DOM, без Drizzle и Hono. Он должен одинаково собираться для браузера и сервера.
- Структура: файл на домен (`auth.ts`, `profile.ts`, `schedule.ts`, `grades.ts`, `requests.ts`, `notifications.ts`, `staff.ts`, `certificates.ts`), всё реэкспортируется из `index.ts`.
- Именование: схема `XxxSchema`, тип `Xxx`. Для входа `XxxInputSchema`, для ответа — `XxxSchema`.
- Роуты описаны константами в `routes.ts` (метод, путь, схема входа и выхода). И сервер, и клиент берут пути отсюда, а не пишут строки руками.
- Статусы и типы — `z.enum([...])` со строковыми значениями на английском (`submitted`, `in_review`, `ready`, `rejected`). Русские подписи живут во фронте.
- Даты передаются ISO-строками (`z.iso.datetime()` / `z.iso.date()`), время пары — `HH:MM`.
- Формат ошибки API один на всё: `{ error: { code: string, message: string } }` (`ApiErrorSchema`).
- Внутренних полей (хеши, служебные id) в DTO нет.
- Если меняешь существующую схему, проверь, что `pnpm typecheck` проходит во **всех** пакетах.
