# Модуль web

Критерий «Качество» жюри оценивает по ощущению: цельный стиль, нужное находится быстро, хочется пользоваться каждый день.

## Мобильный сначала
- Вёрстку начинаем с ширины **360 px**, десктоп — это расширение. На 360 px нет горизонтального скролла.
- Навигация: на телефоне нижний таб-бар (Главная, Расписание, Успеваемость, Заявки, Ещё), на десктопе боковое меню.
- Зоны касания не меньше 44×44 px. Важное доступно в 1–2 касания.

## Дизайн-система
- Цвета, шрифты, отступы, радиусы и тени задаются токенами (CSS-переменные + тема Tailwind). Хардкод цветов и `px` в компонентах запрещён.
- Базовые компоненты лежат в `src/ui/` (на основе shadcn/ui), фичи собираются из них. Прежде чем делать новый компонент, проверь, нет ли такого в `src/ui/`.
- Поддерживаются светлая и тёмная темы через токены.

## Состояния
У каждого экрана с данными есть все четыре состояния:
- **loading** — скелетон, не голый спиннер;
- **empty** — понятный текст и действие («Заявок пока нет — заказать справку»);
- **error** — человеческое сообщение и кнопка «Повторить»;
- **данные**.

У форм есть валидация на месте, заблокированная кнопка во время отправки и явный результат.

## Доступность
Контраст не ниже WCAG AA, видимый фокус, `aria-label` у иконок-кнопок, семантические теги (`button`, `nav`, `main`, `h1…`), всё работает с клавиатуры. Статусы не передаются одним цветом: нужны текст или иконка.

## Данные
- Запросы идут только через типизированный клиент `src/api/` поверх `@aihs/contract` и TanStack Query. Импорты из `apps/api` запрещены.
- MSW-моки в `src/mocks/` строятся по схемам контракта и включаются env-флагом. В проде их нет.
- Даты и время показываем в Europe/Moscow на русском.

## Тексты
Интерфейс на русском, тон дружелюбный и короткий, без канцелярита. Подписи статусов и типов заявок лежат во фронте (в контракте только коды).

## e2e
Playwright проверяет ключевые сценарии на вьюпорте 360×800 и на десктопе. Селекторы — по роли и тексту (`getByRole`), а не по CSS-классам.
