## Этап 1. MVP ядра ★ — 19–20.11

**contract**
- схемы дополнены по ходу этапа, фронт и бэк собираются на одних типах

**api**
- схема БД: users (role: student/staff), students, faculties, groups, teachers, lessons + changes, subjects, grades, requests + history, notifications, sessions
- сид: вымышленный вуз, **2 студента** из разных групп с разными данными + **1 сотрудник**; расписание считается от текущей недели (Europe/Moscow), есть переносы и субботние пары
- auth: login / logout / me, argon2id, сессия в httpOnly cookie, rate-limit на логин
- `/api/me/profile`, `/api/me/schedule?week=`, `/api/me/grades`, `/api/me/notifications` (+ отметка «прочитано»)
- заявки: типы справок и заявлений, создание, список, детали с историей статусов (только свои)
- staff: очередь заявок, смена статуса с комментарием → студенту приходит уведомление
- интеграционные тесты, включая IDOR (студент A → заявка B → 404; студент → `/api/staff/*` → 403)

**web**
- дизайн-система: токены (цвет, шрифт, отступы, радиусы), базовые компоненты, скелетоны, empty/error
- мобильный каркас: нижний таб-бар на телефоне, боковое меню на десктопе
- логин (ошибки, загрузка), профиль
- расписание: «сегодня» и «неделя», аудитория и преподаватель, переносы заметно выделены
- успеваемость: оценки и зачёты по дисциплинам, сессия, сводка «как у меня дела»
- заявки: мастер подачи, список, карточка со статус-таймлайном
- уведомления: лента, непрочитанные, бейдж
- кабинет сотрудника: очередь заявок, смена статуса
- переход с MSW на реальный API

**deploy**
- прод на ВМ: HTTPS, Postgres с томом, миграции и сид при старте, тестовые аккаунты работают

★ **MVP для демо готов, когда на проде:** входим двумя студентами и сотрудником → смотрим расписание и оценки → студент подаёт заявку → сотрудник меняет статус → студент видит статус и уведомление. Всё проходится на ширине 360 px.
